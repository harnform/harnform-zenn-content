# 「次は気を付ける」を11回やって、ようやく表に逃がした話

最初は、こんなの表にするほどでもないと思っていました。毎回ちょっと見直せば足りるし、抜けても次は気を付ければいいだろ、くらいの感じでした。

その言い方で、たぶん2ヶ月くらいごまかしていたと思います。

ある日ふと、自分用の見直しメモが手元で12個に固まっていました。整理したかったというより、忘れても回るようにしたかっただけでした。

副業で AI にコードを書かせていて、自分が最後のレビュー係をやらされていた話を、いったん書き残しておきます。

## 「次は気を付ける」で済ませていた時期が長かった

最初は、毎回その場で見直せば足りると思っていました。AI が書いてきたコードを自分で読んで、変だなと思ったら止めて、直して、回す。それで十分だろ、と。

実際、最初の数週間はそれで足りていました。

困り始めたのは、1回の大事故ではなくて、小さい呼び戻しが何回も続くようになってからでした。

朝、コーヒーを入れてからログを開く前に、少し間を置くようになっていました。あれ、また何か止まってるかも、と思う時間が地味に嫌でした。

> またここ？

中身を見ると、ほとんどが「前回もここで詰まったやつ」でした。引き継ぎが雑で前提が抜けていた、retry の方針が決まっていなくて止まっていた、戻せない状態のまま走らせていた、みたいな。

毎回「今回はたまたま」「次は気を付ける」で済ませていました。いや、何回言うんだそれ。

たぶん10回目くらいまでは、本気で自分の頭で毎回見直せると思っていました。11回目あたりで、ようやく自分の頭の容量が無理だと認めました。

## 結局、自分が最後のレビュー係をやっていた

AI に任せているつもりだったんですが、気付くと自分が最後の見張り役をやっていました。

planner と coder を分けて、設計と実装を別人格にして、preflight でブリーフィングを入れて、wave で並走させて、retry で粘らせて。それでも結局、最後に「これで本当に大丈夫か」を見るのは自分でした。

しんどかったのは、見落としが派手じゃないことでした。

- 切り方が雑で、1人に重さが寄っていた日
- 引き継ぎが短すぎて、前提が抜けたまま次に流れた日
- 独立してる作業を順番待ちさせていた日
- 逆に同じファイルを2人に触らせて、あとで面倒になった日

> これ、誰が見るんだっけ

そう独り言が出る日が増えました。AI を使っているはずなのに、自分が AI の検査官みたいになっていました。

「自分で全部確認したい」気持ちと、「全部自分が見るのは無理」という気持ちが矛盾していました。矛盾したまま、けっこう長く回していました。

## 抜け方にだいたい癖があると、遅れて気付いた

何回も呼び戻されて、ようやく抜け方に癖があるなと気付きました。

毎回違うところで壊れているわけではなくて、だいたい同じ場所で同じように抜けていました。

- 起動前に過去の失敗を渡さないまま走らせて、同じミスを踏む
- 重い依頼を重いまま投げて、途中でお腹いっぱいになって帰ってくる
- exit 1 を見て「もう一回」で済ませて、同じ止まり方を2回やる
- timeout の境目が曖昧で、抱え込んだまま長引く
- 戻せない状態にしてから、そこでようやく怖くなる

「いや、なんで」と言いたくなる頻度が、ある時期から急に上がりました。

正確には、頻度が上がったわけではなくて、たぶん最初からこのパターンで踏んでいたんだと思います。気付いていなかっただけでした。

その場の勘で retry させたり、なんとなく見守ったりするのを、いったんやめることにしました。やめたというか、続けるのが普通に疲れた、という方が近いです。

## 4つに分けて手元に置いたら、迷う回数だけ少し減った

12項目に固まったのは、最初から狙ったわけではないです。

最初は2項目くらいだったんですが、踏むパターンが増えるたびに足していって、いまの形になりました。整理したかったというより、毎回その場で迷うのが嫌だっただけです。

便宜上、4つのブロックに分けています。3つずつ入っています。

| ブロック | 中身（雑に書く） |
|---|---|
| 切り方まわり | 1人に全部やらせない / 引き継ぎを書く / 役割を分ける |
| 走らせ方まわり | 起動前に過去ミスを渡す / 並走できるものは並走 / 同じファイル競合を避ける |
| 止まったとき | 1回 exit 1 で諦めない / 抱え込まない境目を決める / 戻せる状態を作っておく |
| 見る側 | 何を見ているか書く / 見ているログ自体を疑う / 同じエラーで2回止まったら経路を変える |

立派に書きたいわけではなくて、毎回これを脳内でやり直すのが、ある時から続かなくなった、というだけの話です。

特に効いたのは、「並走できるもの / ぶつかるもの / 人間に戻すもの」の分け方を最初に決めることでした。これだけ先に決まっていると、走らせる前の判断が3秒くらいで終わります。3秒で終わるかどうかが、続くかどうかにかなり効きます。

動作確認も、実行しているのと同じところでログを見るのをやめて、別の Bash で見るようにしました。**見ているログ自体が壊れているの、結構怖かったです。** これに気付いたのは、観察してるつもりで観察してなかった日が何日かあったあとでした。

## 置いても防げない抜けはあって、そこはまだ普通に残った

12個並べたあとも、防げない抜けは普通に残っています。

- 認証まわりは、今でも詰まったら即戻すしかない場面がある
- 設計の分岐は、最後はまだ人間が決めるしかない
- 観察期間を切らないと、救済のつもりで延命し続けてしまう
- 「これくらい大丈夫」で例外を作るのは、相変わらず自分だった
- preflight を飛ばした日が何回かある。分かっていたのに飛ばしたやつ

特に最後のやつは、自分でも変だなと思いました。書いたチェックを、自分で守れない日がありました。

「ちゃんと直して、ちゃんと忘れる」みたいな日が、たぶんこれからも出ると思います。

なので、全部は防げない前提で、止める線だけ先に決めるようにしました。観察期間を切る、KILL条件を先に書く、3アプローチ全滅で人間に戻す、みたいな粗いラインです。

これも完成形ではない気がしています。たぶん、止める線も、また書き直すと思います。

## いまは自分用の見直しメモとして置いている

12個に固まってから、見直しの形は少し落ち着きました。

毎回その場で考え直さなくていいぶん、コーヒーを淹れてから ログを開くまでの時間が、少し短くなった気がします。気のせいかもしれません。

最近、似た話を聞くことが少しずつ増えました。

> AI を使ってるのに、自分が確認の係に回っている
> 同じところで毎回詰まるけど、その場で対応している
> 「次は気を付ける」を毎週言っている

たぶん、自分の頭で毎回ぜんぶ思い出そうとしているのが、続かない原因なんだと思います。

私の場合は、誰かに教えるというより、自分がまた同じ朝を迎えないために書いていました。販売したかったわけでもなく、ただ手元に置いておきたかっただけです。

中身は、切り方 / 走らせ方 / 止まり方 / 見る側、で4ブロック × 3項目です。同じところで詰まっている人向けに、いったん有料記事として整理しています。完成版というより、いま困っている自分が使える形を優先しました。

たぶんまた、項目は増えたり減ったりすると思います。これが最終解だとは、まだ思っていません。
