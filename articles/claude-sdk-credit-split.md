# claude -p のクレジットが分離されるらしい、うちへの影響メモ

2026-06-15 から Claude の各プランに「Agent SDK 専用クレジット」が分離支給される予定らしい。

発表内容を読んだ限りでは、`claude -p`（headless mode）、Claude Agent SDK 経由、第三者アプリ経由の利用が通常の interactive 利用とは別建ての credit 枠になるとのこと。Pro $20/月、Max 5x $100/月、Max 20x $200/月というプラン別の専用枠が設けられて、rollover なし（月末 expire）、枠切れ後は extra usage（標準 API レート、要 opt-in）という設計のようだ。

うちは Claude Max 20x $200/月相当を使っていて、`claude -p` をかなりヘビーに回している構成なので、この変更は直接関係してくる可能性がある。以下は「うちにはこう影響しそう」という個人メモ。事実確認は公式ドキュメントを当たってほしい。

## うちの claude -p 依存状況

まず、どのくらい `claude -p` を回しているかを整理しておく。

systemd timer で動いているものをざっと挙げると、Zenn 記事の自動公開（zenn-activate.timer）、日次の KPI スナップショット（kasegu-kpi-snapshot.timer、23:30 daily）、SNS ペルソナの自動投稿 timer（複数）、quant の lv4 pipeline、株系・暗号資産系・FX 系 bot の各種 cron 等。それぞれが `claude -p` か Agent tool 経由のサブエージェント呼び出しを使っている構成になっている。

ログを集計すると、直近 30 日の Anthropic SDK 経由（sonnet 系メイン）は 887 件・55.2M token・$329 という数字が出ている。これが全部 `claude -p` / Agent SDK 経由かというとそうではないが、相当な割合が含まれているはず。

> 55M token、多いな。

これを見たとき、「Max 20x $200 の枠で収まっているのか？」とすこし不安になった。収まっているはずなのに 55M というのは、token 単価の計算が合っていないのか、それとも interactive 分が含まれているのか、ログの集計粒度が荒いのか、今ひとつ分からないまま動かしている。

## 分離支給で何が変わるのか

これまでは interactive（Claude.ai での会話）も `claude -p` も同じ枠から消費されていた（はず）と理解していた。それが 6 月以降は別建ての枠になるらしい。

直感的には、「普段の会話で枠を使い切っても、agent/SDK 用の枠は残っている」「逆に夜の自動実行が暴走しても、翌日の interactive 枠には影響しない」という設計になりそうということ。これは理屈の上では助かる方向。朝に claude.ai を開いたら「枠が切れています」になる、という事態は避けたい。

ただ、rollover なし（月末 expire）という点は少し気になっている。うちの場合、月末に向けて bot の発火が重なりやすい（月次レポート生成・KPI 集計が月末に集中）ので、月末だけ枠が足りなくなって extra usage に切れ込む可能性がある。extra usage は標準 API レートで要 opt-in とのことなので、opt-in していなければ月末に失敗するだけで済むが、opt-in すると予想外の請求が来るリスクがある。

## Max 20x $200 の枠で足りそうか

正直、今の消費量と Max 20x の枠の対応がよく分かっていない。

「Max 20x $200/月」というのは、Agent SDK 専用クレジットが月 $200 分、という意味なのか、プラン全体が $200 でその中に SDK クレジットが含まれるのか、現時点の公式ドキュメントを読んだ限りでははっきりしなかった。

ログ上の $329（sonnet 887件分の概算）という数字が正しいとすると、$200 の枠を超えている計算になる。ただし sonnet の単価計算が実際の Max 20x 契約上のレートと合っているかが不明なので、この数字をそのまま当てはめるのは無理がある。

実際の請求明細を見た記憶では月の請求が $200 前後に収まっているので、何かしらの差異があるんだと思う。この「ログ上の概算と実際の請求の乖離」はずっと分からないまま放置している。6 月以降に分離クレジットで明細が見やすくなれば、ここが解消されるかもしれない。

## 試したが整理できていないこと

claude -p の消費と interactive の消費を分けてログを取ろうとしたことがある。

`LoggedAnthropicClient` に `source` フィールドを入れて、agent 起動時に識別子を渡す設計にしているんだが、サブエージェント呼び出しの内側で何が起きているかは外から見えない。Agent tool を呼ぶと内部で claude を呼ぶが、その呼び出しのトークンがどこに記録されているかが追えていない。

なので「55M token のうち何%が claude -p 経由か」は今の段階では分からない。この区別が公式で明細として出るようになれば、ようやく実態が見えるかもしれない。

## 未確定点

現時点でまだ分からないことを書いておく。

- 第三者アプリ経由（Cursor、Windsurf 等）はどう扱われるか
- extra usage の opt-in は何をもって「同意」とするか（設定画面か請求開始時か）
- interactive か claude -p かの判定境界（ターミナルから呼べば headless 扱いか）
- Max 20x の Agent SDK 専用クレジットが月 $200 分なのか、プランの $200 に内包されているのか

最後の点は最も気になっていて、もし「$200 のうち一部が SDK 枠、残りが interactive 枠」という分割なら、現状から実質的な枠が小さくなる可能性がある。発表記事を読む限りではこの点が読み取れなかったので、6 月に実際の請求明細を見るまで確信が持てない。

## うちはどう構えるか

今のところ考えていること。

まず extra usage の opt-in はしばらく保留するつもり。opt-in していなければ枠切れになっても追加請求は来ない。月末に一部の cron が失敗するとしても、把握できていない追加請求が来るより把握できた失敗のほうがまし。

次に、月末に重なりやすい処理（月次レポート・KPI 集計）のスケジュールを月中旬に前倒しする案を検討している。今は月末 23:30 に集中させているが、これが枠の月末切れと重なると毎月同じ場所で詰まることになる。

それと、claude -p 経由の消費を source タグで追えるように logging を直したい。今は全部 anthropic_sdk 扱いになっているせいで、interactive と agent の消費比率が分からない。分離クレジット導入後に明細を正確に読めるようにするには、こちら側のログ設計を先に直しておく必要がある。

ただ、上記のどれも「6 月以降の実際の請求を見てから」でないと優先度が決められない。今できることは、現状のログを拾える範囲で整理しておいて、6 月の明細が出たときに素早く判断できる状態を作ること、くらいだと思っている。

最近、周りでも似た話を聞くことが増えた。

「claude -p を cron で回しているが、月いくらかかっているか把握できていない」
「Max 20x を使っているが token 換算で足りているのか毎月不安」
「分離クレジットになったら把握しやすくなりそうだけど、枠が足りなかったとき怖い」

うちも同じ感覚でいる。分離して見えやすくなるのはいいが、現状どれくらい使っているかをちゃんと把握できていないまま 6 月を迎えそうで、そこが少し不安。

まだ整理しきれていない状態でメモしている。6 月に実際の明細が出たらもう少し整理できると思う。
